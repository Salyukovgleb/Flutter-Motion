# Участие в разработке

Единственный источник требований — [спецификация](flutter_motion_guide_v2.md),
включая согласованные уточнения в её начале. Выполняйте шаги 1–20 по порядку,
не переходя дальше до выполнения условия «Готово, когда».

Каждому шагу соответствуют отдельная ветка и один Conventional Commit или PR.
Перед реализацией перечислите планируемые файлы. Тесты пишутся вместе с кодом.
Изменения публичного API требуют ADR в `docs/adr/`; новые методы сначала
согласуются с владельцем. Генерируемые шаблоном демонстрационные API не входят
в библиотеку.

## Перед коммитом

Из корня репозитория выполните:

```sh
dart format .
dart analyze --fatal-infos
dart run melos run analyze --no-select
dart run melos run test --no-select
git diff --check
```

Для Flutter-пакетов Melos запускает `flutter analyze --fatal-infos
--fatal-warnings`, для чистого Dart — `dart analyze --fatal-infos`.
Предупреждений, информационных замечаний и упавших тестов быть не должно.
Артефакты покрытия не коммитятся; общий `pubspec.lock` коммитится.
При добавлении исполняемых строк пороги покрытия: ядро ≥90%, Flutter-слой ≥80%.

## Ограничения

- `motion_core` не импортирует Flutter, `dart:ui` или сторонние runtime-пакеты.
- В горячих путях кода библиотеки не создаются объекты, замыкания и коллекции;
  неизбежные аллокации Flutter учитываются отдельно при профилировании.
- Покадровое обновление не перестраивает дерево через `setState`.
- Доступность, reduced motion, hit testing и lifecycle проверяются тестами.
- Dartdoc и идентификаторы — английские; README и `docs/` — русские.
- После шагов 5, 8, 10, 12, 13 требуется демо-проверка владельцем на устройстве.
- Публикация на pub.dev и развёртывание сайта требуют явного разрешения владельца.
  Push выполняется только в пределах его явного разрешения.

Отчёт шага содержит список файлов, реальные результаты проверок и покрытия,
проверку каждого критерия готовности, отступления и следующий шаг.
