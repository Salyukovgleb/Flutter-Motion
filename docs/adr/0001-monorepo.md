# ADR 0001: монорепозиторий Flutter Motion

- Статус: принято владельцем.
- Дата: 2026-11-03.
- Область: шаг 1, инструменты и структура; публичный анимационный API не вводится.

## Контекст

Ядро должно работать без Flutter и `dart:ui`, а Flutter-слой должен использовать
его через обычную зависимость. Расширения добавляются позднее и не зависят друг
от друга. Имена `motion` и `flutter_motion` уже заняты на pub.dev. Владелец выбрал
имя `kinetic_motion` для Flutter-пакета; название проекта остаётся Flutter Motion.
На момент проверки реестр pub.dev не содержал `kinetic_motion`; это не
резервирование имени.

## Решение

Используем Dart pub workspace с явными путями `packages/motion_core` и
`packages/kinetic_motion`, `resolution: workspace` и общим lockfile в Git.
Версия исходного окружения: Flutter 3.41.2, Dart 3.11.0. Нижняя граница SDK
пакетов соответствует проверенному окружению; совместимость с более старыми
SDK пока не заявляется. CI закреплён на Flutter 3.41.2 для воспроизводимости.
Матрица двух актуальных стабильных Flutter добавляется при проверке
совместимости по разделам 8–9 спецификации, до релиза.

Melos 7.8.2 закреплён как dev dependency корня; конфигурация находится в
`pubspec.yaml`, отдельного `melos.yaml` нет. `dart run melos` использует локальную
версию. Скрипты вызывают вложенные команды через `dart run melos`, поэтому
работают и без глобального executable в PATH. `lints` — dev dependency корня; пакеты наследуют общие настройки анализа.

`motion_core` не имеет runtime-зависимостей. `kinetic_motion` зависит только от
Flutter SDK и локального ядра. Все дополнительные пакеты из структуры
спецификации создаются только на своих шагах. `motion_shaders` не создаётся:
для него нет шага и требований реализации.

Оба CI job устанавливают Flutter, поскольку pub разрешает весь workspace,
включая Flutter SDK dependency. При этом ядро выполняется через `dart test`
в обычной Dart VM. CI проверяет формат, строгий анализ и все тесты; покрытие
сохраняется как артефакт. Runner закреплён на Ubuntu 24.04; checkout 7.0.1 и
upload-artifact 7.0.2 используют Node.js 24 и не вызывают предупреждений об
устаревшем Node.js 20.

Шаблонные `Awesome` и `Calculator` удалены. Точки входа библиотек пока пустые.
Тесты проверяют загрузку точек входа, допустимые зависимости исходников ядра и
отсутствие запланированных кадров при загрузке Flutter-пакета. Для нуля
исполняемых строк покрытие равно 0/0 и не объявляется ни 0%, ни 100%.
Пороговые проверки появятся вместе с исполняемой реализацией: ядро ≥90%,
Flutter-слой ≥80%.

Согласованные исправления заготовок собраны в начале спецификации. Они имеют
приоритет над историческими фрагментами кода и реализуются на соответствующих
шагах, без перехода к ним раньше времени. Внешний исходный файл в Downloads
не изменяется; рабочий источник требований — файл в этом репозитории.

## Последствия

Общие зависимости разрешаются совместно. Flutter SDK нужен для bootstrap
монорепозитория, хотя исходники ядра остаются чистым Dart. Контроль версий SDK и
общий lockfile обеспечивают совпадение локальных проверок и CI. Смена имени
пакета меняет импорты, но сохраняет `.motion()` и имена типов из спецификации.
