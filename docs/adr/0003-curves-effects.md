# ADR 0003: кривые и эффекты чистого ядра

- Статус: реализация согласованной спецификации шага 3.
- Дата: 2026-11-03.
- Область: кривые и эффекты `motion_core`; основной Flutter API не расширяется.

## Решение

Экспортируются только символы из шага 3: `EaseFn`, `Ease` с linear, outCubic,
inOutCubic, outBack, spring, dampedSine; `EffectState`, интерфейс `Effect` и
шесть эффектов Fade, Move, Scale, Rotate, Shake, Pulse. Конструкторы, параметры,
умолчания и формулы соответствуют спецификации. Публичные символы снабжены
английским dartdoc с примерами. Зависимости ядра не меняются.

EffectState создаётся один раз для цели. reset возвращает все поля к identity.
Эффекты не сбрасывают состояние: смещение и поворот складываются, масштаб и
прозрачность умножаются. Они не меняют не относящиеся к ним поля, включая anchor.
hasTransform учитывает только смещение, масштаб и поворот.

Нормализованный прогресс в общем случае равен 0..1. Результат easing может
выходить за границы: эффекты не ограничивают его, иначе потеряется отскок.
Порядок эффектов одного этапа не меняет результат с точностью арифметики double.
Состояние между кадрами явно сбрасывается; сами эффекты не хранят историю.

## Горячий путь

В apply и reset нет конструирования объектов, замыканий, коллекций и результата
record. Для интерполяции точные t == 0/1 возвращают заданные границы без потери
малого конечного значения при вычитании больших чисел. Pulse на границах
оставляет масштаб без изменений, устраняя остаток sin(pi). Это численные
реализации исходных формул, без изменения публичного контракта.

Ease.spring создаёт и кеширует функцию вне вычисления кадров. Вычислитель
приватный и возвращает только double, используя заранее подготовленные
коэффициенты траектории Spring.bounce(duration: 1). В отличие от заготовки он
не вызывает публичный Spring.solve с record-результатом на каждом sample.
Это выполняет уже согласованное уточнение 7 об отсутствии временных объектов
в горячем пути. Новой публичной функции вычисления пружины не добавляется.

Для нулевого отскока используется критическая формула; для положительного —
недодемпфированная. Нулевой damping здесь не возникает: фабрика Spring.bounce
ограничивает bounce сверху 0.95. Начало и конец пружинной кривой возвращают
ровно 0.0 и 1.0, как требует спецификация. Кеширование происходит по исходному
значению bounce, как в заготовке. Неконечный bounce отвергается физической
фабрикой; конечный ограничивается её диапазоном. Обычные easing-функции и apply
не вводят новых проверок параметров вне заданного контракта прогресса.

Отсутствие явных аллокаций проверено по коду; гарантия о поведении компилятора
и общей стоимости кадров требует последующего AOT/profile-замера. Математические
unit-тесты не выдаются за профилирование приложения.

## Проверка

Кривые проверяются в граничных и промежуточных точках, на монотонность,
симметрию, отскок и детерминированность при обратном порядке вызовов.
Приватный scalar-расчёт сравнивается с публичным аналитическим Spring.solve
на 900 samples с фиксированным seed, включая почти критическое затухание.

Каждый эффект проверяется при t = 0/0.5/1 на неединичном состоянии, чтобы
проверить накопление результата и сохранение остальных полей. Дополнительные
проверки охватывают пики shake, точные конечные состояния, пропуск overshoot,
переиспользование state, реализацию внешнего Effect и 100 перестановок цепочки
с фиксированным seed. Общий порог покрытия ядра ≥90% остаётся обязательным.

## Границы шага

Таймлайн, кадры Flutter, reduced motion, hit testing и визуальная галерея
остаются на соответствующих следующих шагах. В шаге 3 нет Flutter-импортов,
покадрового setState и дополнительных публичных возможностей.
