# ADR 0002: аналитическая пружина ядра

- Статус: принято в рамках согласованной спецификации шага 2.
- Дата: 2026-11-03.
- Область: публичный `Spring` и его API из шага 2; основной набор Flutter API не расширяется.

## Контекст

Пружина должна вычислять положение и скорость без привязки к шагу кадров,
сохранять скорость при будущем перенацеливании и работать в чистой Dart VM.
Заготовка использует const-конструктор с assert, которые не защищают release,
а при нулевом damping формула времени покоя делит на ноль.
Согласованные уточнения требуют проверки входов в release и сохранения API.

## Решение

Публичный API ровно из спецификации: `Spring`, const-конструктор с stiffness,
damping, mass, фабрика `Spring.bounce`, пресеты smooth/snappy/bouncy,
поля параметров, `settleTime` и `solve` с record `(double x, double v)`.
Новых публичных символов сверх этого набора нет.

Const-конструктор хранит значения. Физические параметры проверяются при
`solve` и `settleTime`, фабрика проверяет собственные аргументы сразу.
Так соблюдаются const-совместимость и валидация без assertions. Stiffness и mass
положительны, damping неотрицателен; параметры и входы solve конечны.
Непредставимые производные параметры отклоняются с ArgumentError.
Конечный bounce по исходной спецификации ограничивается диапазоном 0..0.95.

Нулевая длительность физической фабрики не допускается; duration задаётся
в секундах и остаётся приблизительным параметром характера движения.
При bounce == 0 затухание критическое, движение из покоя не перелетает цель.
Нулевое damping разрешено и означает незатухающие колебания;
settleTime в этом случае равен double.infinity.

Используется аналитическое решение всех трёх режимов затухания. При t == 0
положение и скорость возвращаются точно. Отрицательное конечное время
вычисляет ту же аналитическую траекторию назад. В solve критическая ветвь
применяется только при точном критическом коэффициенте: близкие режимы не
подменяются критическим приближением. Эквивалентная запись медленного корня
через обратную величину и разделённая разность экспонент уменьшают потерю
точности в сильно затухающем и почти критическом случаях. Для малого аргумента
разности используется ряд с погрешностью ниже точности double в выбранном диапазоне.
Оценка settleTime остаётся приблизительной, как задано в спецификации.

Все публичные символы имеют английский dartdoc с примерами. Record результата
сохранён согласно спецификации; внутренний путь без временного record для
кадрового SpringValue будет реализован на шаге 5, без расширения публичного API.

## Проверка

Тесты проверяют все режимы, начальные условия, знак скорости, сходимость,
монотонность без отскока, перелёт bouncy, сохранение энергии незатухающей
пружины, временную композицию и обратное время. Независимый эталон — численное
интегрирование Рунге—Кутты четвёртого порядка. Property-тесты имеют фиксированный
seed и проверяют 100 наборов параметров. Отдельный процесс с выключенными
assertions подтверждает release-валидацию.

Начиная с этого шага test:core формирует LCOV штатным `dart test --coverage-path`.
Скрипт tool/check_coverage.dart требует минимум 90% строк, отклоняет пустой или
отсутствующий отчёт и считает уникальные пары файл/строка по DA, а не доверяет
итоговым счётчикам LF/LH. Проверка самого порога покрыта тестами. Новых зависимостей
ради покрытия не добавляется. Flutter-слой всё ещё пуст, его порог включается при
появлении исполняемого кода.

## Ограничения

Как у любого double-вычисления, произвольно большие состояния, скорости или
обратное время могут вызвать переполнение. Аналитическое решение не является
гарантией представимости любых комбинаций конечных double. Оценка settleTime
не является строгой границей для произвольной начальной скорости.

Требования производительности кадровых tick/apply/paint/update не подтверждаются
этими математическими тестами: соответствующие части библиотеки пока отсутствуют.
